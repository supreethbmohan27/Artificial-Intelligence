# LLM API Comparison Tool

A Python-based command-line application for comparing OpenAI GPT and Anthropic Claude models using the providers' official SDKs.

The project evaluates LLM responses based on latency, token usage, estimated API cost, and response quality. It supports streaming, configurable system prompts, automated benchmarking, and JSON result storage.

## 1. Features

- Integration with OpenAI and Anthropic APIs
- Support for streaming and non-streaming responses
- Custom system prompts
- Response latency measurement
- Time-to-first-text measurement for streaming responses
- Input and output token tracking
- Estimated API cost calculation
- Ten-prompt benchmark covering multiple task categories
- JSON result storage
- Dry-run mode for validating commands without API requests
- Automated testing using pytest

## 2. Technology Stack

- **Language:** Python 3.12
- **LLM Providers:** OpenAI and Anthropic
- **SDKs:** `openai`, `anthropic`
- **Environment Management:** Python virtual environment, `python-dotenv`
- **Testing:** `pytest`
- **Data Format:** JSON

## 4. Installation

### Prerequisites

- Python 3.12
- pip
- OpenAI API key
- Anthropic API key

### Clone the repository

```bash
git clone <your-repository-url>
cd wynisco
```

### Create and activate a virtual environment

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

For Windows:

```powershell
.venv\Scripts\activate
```

### Install dependencies

```bash
python -m pip install -r requirements.txt
```

## 5. Environment Configuration

Create a `.env` file in the project root:

```env
OPENAI_API_KEY=your_openai_api_key
ANTHROPIC_API_KEY=your_anthropic_api_key
```

The application loads these credentials using `python-dotenv`.

**Security:** Never commit the `.env` file or API keys to GitHub.

## 6. Running the Application

### Compare both providers

```bash
python ask.py "Explain retrieval-augmented generation"
```

This sends the same prompt to OpenAI and Anthropic and displays their responses and usage metrics.

### Use a custom system prompt

```bash
python ask.py "Explain embeddings" --system "You are an AI instructor"
```

### Enable streaming

```bash
python ask.py "Explain AI agents" --stream
```

Streaming displays generated text incrementally and measures time to first text.

### Run without making API requests

```bash
python ask.py "Explain RAG" --dry-run
```

### Validate streaming configuration without API requests

```bash
python ask.py "Explain RAG" --stream --dry-run
```

Dry-run mode validates CLI inputs but does not generate model responses.

## 7. Performance Metrics

The application tracks the following metrics:

| Metric | Description |
|---|---|
| Latency | Total time taken to generate a response |
| Input tokens | Tokens consumed by the input |
| Output tokens | Tokens generated by the model |
| Time to first text | Time until the first streamed text arrives |
| Estimated cost | Calculated using token usage and configured pricing |

### Cost calculation

```text
Input Cost = (Input Tokens / 1,000,000) × Input Price

Output Cost = (Output Tokens / 1,000,000) × Output Price

Total Cost = Input Cost + Output Cost
```

Prices are configured in `src/pricing.py`.

**Important:** The initial pricing configuration uses illustrative values. Verify current provider pricing before using estimates for financial comparisons.

## 8. Automated Benchmarking

The benchmark contains ten prompts covering:

- Factual knowledge
- Reasoning
- Coding
- Creative writing
- Customer-support classification

Each prompt is submitted to both providers, resulting in 20 planned API requests.

### Validate the benchmark without API requests

```bash
python benchmark.py --dry-run
```

Expected output:

```text
Loaded 10 benchmark prompts.
Providers: OpenAI, Anthropic
Expected requests: 20
Dry run completed. No API requests were made.
```

### Run the live benchmark

```bash
python benchmark.py
```

**Warning:** Live execution requires valid API credentials and available API credits. It may incur charges.

Results are saved to:

```text
results/comparison_results.json
```

Each record includes the prompt, model, generated response, token usage, latency, estimated cost, and execution status.

Failed requests are recorded without terminating the entire benchmark.

## 10. Model Comparison Methodology

Both providers receive the same benchmark prompts.

The comparison considers:

1. **Response quality:** Correctness, relevance, clarity, and instruction-following.
2. **Latency:** Time required to complete each request.
3. **Token usage:** Input and output token consumption.
4. **Estimated cost:** Cost based on configured model pricing.
5. **Customer-support classification:** Ability to classify messages into billing, technical support, and general inquiry categories.

Quality assessment requires reviewing the generated responses; latency and cost alone do not determine which model is better.

## 11. Customer-Support Use Case

One objective of this project is to evaluate which LLM is better suited to customer-support classification.

The benchmark includes examples involving billing problems and technical issues.

A final recommendation will consider classification accuracy, response consistency, latency, and estimated cost.

**Current status:** No final model recommendation has been established because live benchmark results have not yet been collected.
